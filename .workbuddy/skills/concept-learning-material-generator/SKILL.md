# concept-learning-material-generator

> 把"想搞懂 X"这件事变成"打开 HTML 就能学的资料"。

## 这个 Skill 解决什么

学习一个新概念时，最常见的痛点不是「找不到资料」，而是：

1. **资料散乱** —— 一会儿看公众号，一会儿翻文档，一会儿查论文。
2. **抽象难落地** —— 文字定义懂了，但和真实系统对不上号。
3. **缺图、缺反例** —— 没有可视化、没有"反例 / 误区"，印象很快就忘。
4. **读完不知道掌握没** —— 没有自检环节，无法形成闭环。

这个 Skill 把"学一个概念"这件事封装成一个标准流程，让任何 AI 在收到概念名后，按统一模板产出**单文件、可离线打开、含图与交互**的 HTML 学习页。

## 适用场景

| 场景 | 是否推荐 |
| --- | --- |
| 给一个具体概念（如 "Agent"、"Transformer"、"Skill"）做系统化梳理 | 强推 |
| 在团队/学习小组里分享一份"十分钟搞懂 XX" | 强推 |
| 给一个方法论 / 工作流做可视化整理 | 推荐 |
| 给一份会议纪要 / 长文做摘要 | 不推荐（用其他总结类 Skill 更合适） |
| 写代码、写文档 | 不在范围内 |

## 不适用场景

- 用户只想要一句话解释（用普通对话即可，不必生成 HTML）。
- 用户给的"概念"其实是具体问题（如 "我的电脑蓝屏了"），先引导澄清。
- 涉及敏感/涉政/涉未成年人内容，必须拒绝。

---

## 输入约定

调用时只需要给一个**概念字符串**（中文或英文皆可），可附带可选修饰：

```
<概念名> [/ 难度: 入门|进阶|深入] [/ 长度: 短|标准|长]
```

默认：**标准长度、入门难度**。Skill 内部应主动判断目标受众，若无明确修饰，按"零基础也能看懂"的标准写。

---

## 输出规范

**唯一产出**：一个 HTML 文件，路径 `learning-materials/<slug>.html`（slug 全小写、连字符分隔，如 `agent.html`、`llm-context.html`）。

### 必备章节（顺序固定）

1. **顶部 Hero 区**
   - 概念中文名 + 英文名（一句话）
   - 一句话定义（≤ 30 字，必须能区分它和相似概念）
   - "预计学习时间 / 难度" 标签
2. **一句话回答 What / Why / How**（三栏卡片，每栏 ≤ 60 字）
3. **核心机制**（最重要的部分）
   - 至少一张**自包含 SVG 图**（不要外链图片）
   - 文字与图必须互相解释，不要各说各话
4. **3 个递进示例**（从最小到复杂）
   - 每个示例必须**可运行 / 可想象**，不能是伪代码占位
5. **常见误区 / 反直觉点**（至少 3 条）
6. **自检题**（3 ~ 5 题，4 选 1，附答案与解析，点击揭示）
7. **与相邻概念的边界**（一张对比小表）
8. **延伸阅读 / 下一步**（3 ~ 5 条）

### 视觉与风格硬性要求

- **单文件** —— 所有 CSS / JS / 图都内联在一个 HTML 里，离线可开。
- **不使用外部资源** —— 不引用任何 CDN 图标 / 字体 / 框架；如需图标用 inline SVG。
- **响应式** —— 桌面优先，1280px 主断点；同时兼容平板与手机。
- **配色克制** —— 单一主色 + 中性灰阶，1 ~ 2 个辅色。深色 / 浅色模式都做好（默认跟系统 `prefers-color-scheme`）。
- **字体栈** —— 系统字体优先：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。
- **可打印** —— `@media print` 下隐藏交互按钮、保留核心图与文字。
- **无障碍** —— 颜色对比度满足 WCAG AA，关键图加 `<title>` 与 `<desc>`。

### 代码组织建议

```
<!doctype html>
<html lang="zh-CN">
<head>  <!-- meta、title、style（CSS 变量优先） --> </head>
<body>
  <header class="hero"> ... </header>
  <main>
    <section id="what-why-how"> ... </section>
    <section id="mechanism"> ... </section>
    <section id="examples"> ... </section>
    <section id="pitfalls"> ... </section>
    <section id="quiz"> ... </section>
    <section id="boundaries"> ... </section>
    <section id="next"> ... </section>
  </main>
  <script>  /* 仅放交互（如 quiz 揭示） */ </script>
</body>
</html>
```

**禁止**：

- 整页用 `<table>` 做布局。
- 把所有内容塞进一个 `<div>`，没有语义化标签。
- 用 emoji 当章节图标（最多在副标题位置小量点缀）。
- 把外链图片 / 字体直接 `<img src="https://...">`。

## 实施步骤

调用本 Skill 后，按下面顺序执行：

### Step 1 — 澄清与定位（仅在必要时）

如果用户只给了**一个极短、含义模糊**的概念词（例如 "X"、"中间件"），先**用 1 ~ 2 个简短问题确认范围**，不要自行脑补。例如：

> "中间件" 这个词含义比较广 —— 你想偏操作系统/网络方向（进程间通信、消息队列），还是偏 Web 应用层（Express/Redux 这类）？

如果概念本身明确（如 "Agent"、"Transformer"），**直接进入 Step 2，不要为了问而问**。

### Step 2 — 内容大纲（先骨架后填肉）

在动手写 HTML 之前，**先用 Markdown 在心里列一遍 8 个章节的小标题与 1 ~ 2 句核心点**。这一步是质量的关键——很多烂内容就是因为"边写边想"。

### Step 3 — 选主色与视觉风格

每个概念给一个克制的视觉主题色，例如：

| 概念 | 主色 |
| --- | --- |
| Agent | `#6366f1`（靛紫，代表"自主行动"） |
| 大模型上下文 | `#0ea5e9`（天空蓝，代表"流动信息"） |
| Skill | `#10b981`（翠绿，代表"可复用模块"） |

颜色仅用于强调与按钮，不要大面积铺底。

### Step 4 — 写 HTML

按"代码组织建议"一节的结构拼装。**核心机制区**至少含一张图，且 SVG 必须：

- 用 `<title>` 与 `<desc>` 标注（无障碍与 SEO）
- 关键节点用 `<g role="button">` 或 `<text>` 单独标注
- 不要用 PNG / JPG 截图代替图示

### Step 5 — 自检清单（写完后**强制**逐项过一遍）

- [ ] 单文件离线打开正常，无 404 / 跨域报错
- [ ] 8 个必备章节齐全，顺序正确
- [ ] 至少 1 张 inline SVG，`<title>` / `<desc>` 完整
- [ ] 自检题答案点击能揭示
- [ ] 暗色模式切换无颜色崩坏
- [ ] 打印预览（Ctrl+P）主要信息齐全
- [ ] 移动端 360px 宽度下文字不被截断
- [ ] 没有引用任何外部 CDN / 图片
- [ ] 中英文混排没有奇怪的折行（必要时加 `word-break: break-word`）

### Step 6 — 保存与回报

- 保存到 `learning-materials/<slug>.html`
- 在对话里告诉用户：
  1. 路径
  2. 用浏览器或直接预览 HTML
  3. 1 ~ 2 句最重要的"理解这个概念要记住的一件事"

## 质量基线（如何判定这份资料合格）

**及格线**：

- 一个完全不懂这个概念的人看完后，能用自己的话给另一个人讲清楚。
- 至少记住 3 句金句 / 1 张图。
- 知道它和"看起来很像"的另一个概念差在哪。

**优秀线**（难但可达）：

- 让人**愿意把它转发给同事 / 朋友**。
- 让人在 30 秒内找到想要的"误区 / 自检题 / 对比表"。

## 与其他 Skill / 工具的协作

- **visualizer（show_widget）**：如果你想要"对话里就能看到"的版本（SVG 内联卡片），可以用 show_widget 输出迷你图；但完整学习页必须是 `learning-materials/*.html`。
- **brief-compose / tdoc-orchestrator**：如果用户希望把这份 HTML 转成 PDF / DOCX，由用户主动触发；本 Skill 不主动调它们。
- **十进制记忆 .gitignore / Git**：本 Skill 不负责版本管理，由调用方在合适时机 commit。

---

## 已知边界与未来扩展

- 当前不做"按用户阅读时间动态调整难度"。
- 当前不做"自动出题 + 自动判分"。
- 当前所有图都是预渲染 SVG，不做交互式动画。
- 后续可演进方向：内置暗 / 亮模式切换按钮、目录锚点高亮、移动端 TOC 抽屉。
