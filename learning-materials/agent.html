Agent · Autonomous Agent

能感知环境、自主决策、采取行动，并在循环中持续朝目标逼近的 AI 系统。

预计 10 分钟 入门难度 AI · 系统设计

一句话三连

是什么 What

一个会"看情况、动脑子、动手做"的程序。它不只是回答问题，而是能自己决定下一步该干什么。

为什么重要 Why

从"AI 答题"到"AI 做事"，是 LLM 最大的范式跃迁。Agent 让模型可以真实改变外部世界。

怎么实现 How

把 LLM 放进一个"感知 → 思考 → 行动 → 反馈"的循环里，让它能调用工具、读结果、再决定。

核心机制：感知—思考—行动循环

Agent 的灵魂是一个闭环。模型单次回答问题是开环，Agent 引入"行动结果"作为下一步输入，就成了闭环。

为什么是"循环"而不是"一次性"？

因为世界有反馈。一次回答看不到自己是否真的把事做成了；循环能看 —— 失败了就重试，方向错了就调头。这正是 Agent 与普通 LLM 对话最大的区别。

判断一段程序是不是 Agent，关键看：它能不能"看自己刚才干的事的结果"，并据此决定下一步。

三个递进示例

L1 · 最小

单轮"思考—行动"：查天气

用户问"上海今天要带伞吗？"。Agent 不直接答，而是：调用天气 API → 读结果 → 用自然语言答复。

用户："上海今天要带伞吗？"
思考：需要实时天气 → 调用 get_weather("Shanghai")
行动：get_weather 返回 "中雨，25°C"
观察：拿到结果
思考：已经有信息，直接回答
回复："带伞，上海今天中雨。"

这是 Agent 的最小例子。模型本可以"凭印象"瞎答，但 Agent 选择去看一眼真实数据。

L2 · 多步

多步任务：整理桌面文件

用户说"把桌面 PDF 分类到对应文件夹"。Agent 需要：枚举文件 → 读标题判断类别 → 创建/找到目标文件夹 → 移动文件 → 报告结果。整个过程会循环 5 ~ 20 步。

感知：桌面有 38 个文件，3 个 PDF 在桌面上
思考：先看每个 PDF 的标题，再决定去向
  for pdf in pdfs:
      思考：这个 PDF 主题是什么？
      行动：读前 200 字
      观察：标题是 "2025 Q3 财报"
      思考：归到 "财务" 文件夹
      行动：mv file ./财务/2025Q3.pdf
      观察：成功
感知：3 个 PDF 都处理完了
回复：已分别归到 财务/产品/技术 文件夹。
L3 · 复杂

长链 + 自我修正：写代码并提 PR

用户说"修一下登录页那个 bug，提个 PR"。Agent 串起：读 git log 找可疑提交 → 读代码定位 bug → 写修复 → 跑测试 → 测试失败 → 自己看报错 → 改 → 再跑 → 通过 → commit + push + 开 PR。

注意中间出现了"自我修正"：第 2 次跑测试失败，Agent 必须把错误信息当作新的"感知"，重新进入思考阶段。这就是 Agent 的容错能力。

常见误区 / 反直觉点

✕
"Agent = 更聪明的聊天机器人"

错。聊天机器人是开环，Agent 是闭环。判断方式：看它能不能"读取自己行动的后果"。

✕
"Agent 一定要联网 / 一定要用工具"

不一定。Agent 的关键特征是闭环，工具只是闭环的一种实现方式。即使一个 Agent 只通过"读自己刚才写出的草稿 → 修改"也能形成 Agent。

✕
"Agent 越能'自主'越好"

并非。完全自主会带来不可预测成本。生产里的 Agent 通常有"护栏"：工具白名单、最多循环次数、人工确认关卡。

✕
"Agent 一定会成功"

Agent 可能陷入死循环、重复失败步骤、或跑飞。优秀 Agent 的关键设计之一就是"知道自己什么时候该停下来、问人类"。

自检题

点击"显示答案"看解释。

1. 一个程序能"读到自己刚写的代码，再决定下一步"，但完全不用任何外部工具。它是 Agent 吗？

  1. 不是，因为没用工具
  2. 是，因为有闭环
  3. 不是，因为没联网
  4. 是，因为能写代码
答案：B。Agent 的本质特征是闭环（感知行动结果 → 决定下一步），而不是"用工具"。工具只是闭环的一种实现方式。

2. 下面哪个最不像 Agent？

  1. 你让 AI 帮你订机票，AI 自己查航班、比价、选座、下单
  2. 你给 AI 一段长文，它直接给你写一段摘要
  3. 你让 AI 找代码里的 bug，它能自己跑测试、看报错、改完再跑
  4. 你让 AI 整理一堆文件，它能自己读、分类、移动
答案：B。B 是开环：输入长文，输出摘要，没有"看自己行动结果"的环节。A、C、D 都形成了闭环。

3. Agent 在循环里发现"这件事做不了"，下面哪种处理最合适？

  1. 无限循环直到 token 用完
  2. 沉默、不告诉用户
  3. 停止循环，清晰告诉用户哪里卡住、试过哪些方案、建议怎么办
  4. 随机换一个方向继续做
答案：C。生产级 Agent 的核心设计之一就是"知道何时停止并升级到人"。一个 Agent 没有止损机制，本质上就是有缺陷的。

与相邻概念的边界

概念核心区别
Agent vs LLM 对话对话是开环（输入→输出），Agent 是闭环（输出→再输入）。
Agent vs 工作流（Workflow）工作流是预定义步骤序列；Agent 自主决定下一步走哪一步。
Agent vs 机器人流程自动化（RPA）RPA 严格按规则走；Agent 用 LLM 推理应对规则外情况。
Agent vs CopilotCopilot 通常每一步都需要人确认；Agent 可在授权范围内连续执行。
