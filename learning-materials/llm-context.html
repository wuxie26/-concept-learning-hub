大模型的上下文 / LLM Context

Context Window · Prompt · Working Memory

大模型在一次推理中能看见的全部信息（系统提示、对话历史、工具结果、当前输入）。它的长度与质量，决定了模型的"记性"与"工作记忆"上限。

预计 10 分钟 入门难度 LLM · Prompt 工程

一句话三连

是什么 What

模型"眼前"的所有 token。模型看不到窗口之外的事 —— 它的"记忆"本质就是上下文。

为什么重要 Why

上下文 = 模型的工作记忆。上下文短，模型就"健忘"；上下文乱，模型就"偏题"。

怎么管理 How

用 prompt 工程压信息密度，用 RAG 外挂长期记忆，用截断/摘要控制窗口大小。

核心机制：上下文是一份"长 prompt"

每次调用大模型，API 拿到的就是一个有序的 token 序列。模型从前往后读、读完再回答。无论模型内部多复杂，它都"看不见"序列之外的东西。

关键属性

  • 长度（token 数）：模型一次能"看见"的总长度，上限叫上下文窗口（常见 8K / 32K / 128K / 1M+）。
  • 位置（position）：模型对开头 / 结尾的信息记忆最强，中间容易"丢"。这就是常说的 lost-in-the-middle 现象。
  • 成本：输入 + 输出都按 token 计费；上下文越长，单次调用越贵、越慢。
  • 缓存：相同前缀可命中缓存（prefix cache），大幅降低重复调用的成本与延迟。
"模型的智能是固定的，但它的'当下表现'完全取决于你塞进上下文的那些内容。" —— 这是理解 LLM 行为最重要的元规则。

三个递进示例

L1 · 最小

单轮问答：纯当前输入

上下文 = [系统提示] + [用户："把这段话翻译成英文：你好世界"]
LLM 输出："Hello, world."

上下文极小，但已经够用。系统提示设定了"翻译"角色，用户消息提供内容与指令。

L2 · 多轮

多轮对话：让模型"记住"之前说过的话

用户：我叫小明。
助手：你好，小明。
用户：帮我介绍一款适合初学者的相机。
助手：（生成回答）
用户：刚才那款，价格大概多少？
助手：（必须看到前面"刚才那款"指的是什么 → 依靠对话历史推断）

关键：助手不能"记住"，它能"看见"是因为你把所有历史消息都重新拼进了这次调用的上下文。

L3 · 复杂

Agent 上下文：系统提示 + 历史 + 工具结果

系统：你是一个能调用工具的助理，可调用 get_weather。
用户：上海今天要带伞吗？
助手：<tool_call> get_weather("Shanghai") </tool_call>
工具：上海，中雨，25°C。
助手：上海今天中雨，建议带伞。

这里"上下文"包括工具调用与工具返回——模型必须看到工具结果才能给出最终答复。如果工具返回被截断或丢失，模型就只能瞎猜。

常见误区 / 反直觉点

✕
"上下文窗口越大越好"

窗口变大只意味着"能塞更多"。实际表现还受注意力机制影响：很多模型在 32K ~ 128K 中段信息检索能力会下降。窗口长 ≠ 都能用好。

✕
"模型记住的是事实，不是 token"

错。模型没有任何"长期记忆"。它每次调用都是"失忆患者"——你看到它"记得"，是因为上下文里有那段历史。

✕
"只要 token 没超就行"

错。即使没超，"上下文质量"也很关键：冗余信息、矛盾指令、过时的工具结果，都会污染模型判断。

✕
"System Prompt 越长越详细越好"

不一定。System prompt 也是上下文的一部分，写得过长会挤占实际可用空间。建议"必要规则 + 留白"。

自检题

点击"显示答案"看解释。

1. 模型"忘记"一段 30 分钟前的对话，最准确的原因是？

  1. 模型的时间衰减机制
  2. 那次对话已经不在当前调用的上下文里了
  3. 模型的权重没有更新
  4. 对话被模型主动压缩了
答案：B。LLM 没有跨调用记忆；对话"被忘记"，本质是因为旧消息没被拼进新一次的上下文。

2. 在 200K token 窗口里，把关键事实放在最中间，检索效果会怎样？

  1. 和放在开头一样好
  2. 通常比放在开头 / 结尾差
  3. 完全找不到
  4. 取决于模型温度
答案：B。lost-in-the-middle：长上下文里，模型对首尾信息记忆强，中段最弱。要让模型"看见"重要事实，请尽量靠前或靠后放。

3. Agent 跑了几十轮后 token 即将超限，下面哪种处理最不推荐？

  1. 把早期对话摘要后保留摘要
  2. 直接丢掉最旧的几轮
  3. 把工具结果中不再需要的部分清掉
  4. 把整段对话压成结构化笔记
答案：B。直接丢早期对话风险最大：可能丢掉关键前提或约束，导致后续推理脱轨。摘要 / 结构化笔记 / 工具清理 都是更稳妥的策略。

与相邻概念的边界

概念核心区别
上下文 vs 训练数据训练数据是模型权重里的"长期知识"；上下文是当下这次推理能看见的"短期信息"。
上下文 vs RAGRAG 是一种"把外部知识按需塞进上下文"的技术；上下文是更基础的概念，RAG 是它的一种工程实现。
上下文 vs 记忆（Memory）通常"记忆"指的是跨调用持久化的信息；它最终还是要被注入到上下文里才有用。
上下文 vs KV CacheKV Cache 是推理引擎对"已计算的 K/V"做的缓存，目的是省算力；和"用户能塞多少 token"是不同维度。
